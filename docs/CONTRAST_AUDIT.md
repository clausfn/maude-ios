# Contrast audit — PPCN v3 grounds

Generated by `scripts/contrast_audit.py` from `Maude/Theme.swift`. WCAG 2.2 relative
luminance, sRGB. Each token carries its own threshold, because the right threshold
depends on how the token is used: **4.5:1** where it renders as body-size words
(1.4.3), **3:1** where it renders as a mark, fill or stroke (1.4.11).

Grounds — Day: canvas `#FAFAF8` · card `#FFFFFF` · surface `#F3F2EF`.
Night: `#161B22` · `#21262D` · `#1B2028`.

## The headline: the ground move cost nothing

The canvas went from A7.2's cool `#E9F1FA` (relative luminance 0.871) to PPCN's warm
`#FAFAF8` (0.955). **Lighter, not darker.** Contrast is a ratio against the ground, so
every token in the file gained and none lost — the smallest gain was +0.10, and `brass`,
which renders as text, crossed 4.36 -> 4.75 on the canvas, i.e. from failing AA to passing
it. The rebrand introduced no contrast regression anywhere, in either mode. Everything
flagged below is inherited from A7.2 and was already true before the theme was touched.

The fills that sit under 3:1 against the ground — `tirTarget`, `tirHigh`, `devMed`,
`devHigh`, `devOutlier` — are defensible as fills. They are large regions read against
each other rather than against the paper, and each carries its own word, so meaning
survives without the ground contrast doing any work.

**The one real defect this audit found:** `tirTarget` is not only a fill. It is also
used as text:

- `Maude/Views/OuraComponents.swift:198,200` — the band edge figures
- `Maude/Views/OuraComponents.swift:248` — the in-range readout
- `Maude/Views/_GlassLab.swift:135` — `Text("\(tirPct)%")` at 16pt mono

Clinical green on white is **2.05:1**, against a 4.5:1 requirement. The time-in-range
percentage is the most important number on the glucose screen and it is the least
legible thing on it.

The fix is not to move `tirTarget`: RK-ALARM-01 freezes the ramp, and the fill usage is
correct. It is a text-safe sibling used only where the token renders words — exactly
how `clayText` already solves this for amber, which is 1.51:1 as text and therefore
renders its words in ink instead. That is a clinical-display change, so it is recorded
here and waits for CN rather than being taken unilaterally.

Three tokens moved, and only three. `ink3` and `ink4` were carried over from A7.2 with
inline claims of 4.6:1 and >=3:1; measured, they gave 4.37 and 2.85, so both claims were
false. `brass` is used as text in four screens and gave 4.44 on `surface`. Each was
darkened one step at unchanged hue and saturation until its claim became true. The largest
shift is 0.03 in lightness — not a visible change, just an honest one. The table above is
the corrected state.

Still short, and left alone deliberately:

- `amber` — 1.41 against 3.0: the signal amber. Theme.swift already forbids it as small text on a light ground; every call site is a fill or a stroke with a word beside it.
- `clay` — 1.41 against 3.0: the same hex as `amber`, same rule, same call-site shape.
- `fjordBright` — 1.78 against 3.0: PPCN tan, deliberately low-contrast and marked graphic-only in Theme.swift. Solid squares in it require an adjacent label, which the call sites have.
